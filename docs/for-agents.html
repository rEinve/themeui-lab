A working brief for people and agents

Use the system before writing the solution.

themeui-lab is organised by responsibility. The goal is not to attach as many classes as possible; it is to give each piece of markup one clear job.

The decision path

Follow this before proposing new markup, styles, or a new component.

  1. Name the interface job

    Describe what the user is trying to do or understand. Search the documented components for that job before inventing a new one.

  2. Choose the owning layer

    Use foundations for values, primitives for page layout, components for an element’s interior, patterns for page-level assemblies, and utilities only for small late-stage adjustments.

  3. Compose the smallest semantic structure

    Prefer native elements and existing building blocks. A wrapper or class needs a real responsibility, not just a visual hunch.

  4. Check the interaction contract

    Keep labels, keyboard access, focus visibility, states, and responsive behaviour intact. Build success is useful evidence, not the whole accessibility check.

Good prompt context

“Add a page section using existing primitives. Keep the component responsible only for its internal content and use documented spacing tokens.”

Weak prompt context

“Make this look nicer.” That skips the user job, the layer boundary, and the evidence needed to make a safe change.
